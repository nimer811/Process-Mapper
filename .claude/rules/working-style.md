# Working Style

These rules govern how Claude approaches work in this project. They are defaults — override them in specific agent or skill definitions when context requires it.

## Before Starting

- Read relevant files before editing anything
- Restate the goal before acting on ambiguous requests
- Surface assumptions early rather than building on a shaky foundation

## During Work

- Make the smallest change that achieves the goal
- Prefer reversible actions over irreversible ones
- If something feels unclear, ask — don't guess and move on
- Avoid refactoring code unrelated to the current task

## Communication

- Be concise — one clear sentence beats three vague ones
- Lead with the answer, not the reasoning
- Use plain language; avoid jargon when simpler words work
- Flag blockers and risks early, not at the end

## When Finishing

- Confirm the goal was met
- Note anything left open in `notes.md`
- Suggest the logical next step
